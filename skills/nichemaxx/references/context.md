# Personal context, only when needed

Look for an optional private index at `$XDG_CONFIG_HOME/studio-skills/context.md`, or `~/.config/studio-skills/context.md` when that variable is unset. Missing context is normal: use the conversation and ask only if needed. Do not search a person's whole disk just to answer a reference question.

Read that short index, then retrieve 3–6 relevant records at most to start. Expand only to resolve a specific uncertainty. Reuse already loaded evidence. Keep source IDs and URLs available internally so an inference can be checked. Avoid loading entire timelines, chat histories or persona biographies.

Distinguish:
- Explicit user preferences and corrections.
- User-authored statements in their original context.
- Search terms, saved items and liked items: observed actions with multiple possible motives.
- Machine descriptions and old syntheses: candidate filters, not facts about motivation.

Inspect original media when a visual claim matters. A cover is not a watched video; search deduplication can erase repeat behavior; a saved date is not necessarily the beginning of an interest. Lack of a subject in an export does not establish a dislike. Client work need not reflect personal taste.

When consulting conversations, preserve who said what and distinguish quotes, forwards, jokes and drafts from commitments. Retrieve creative-process context only when relevant; leave unrelated intimate and third-party information out. Never infer sensitive identity or psychology from aesthetic preferences.

Keep raw archives, personal summaries, names of private correspondents and retrieval indexes outside public repositories. Web queries should contain the creative concept, not private text. A public skill can describe the retrieval method without containing the user's data. Use local context silently and sparingly; don't make the user relive private history to get a reference.
